# Architectural audit — `Narasimhat/assured-hub` @ `be2a840`

Audited 2026-10-16 against `origin/main` at `be2a840` (41 commits newer than the previously cloned
`0ac667e`). Nothing in `apps/studio`, `apps/qc`, `apps/design` or `packages/*` was changed before this
report was written. Baseline was recorded first: `npm ci`, then `npm test` and `npm run build` at the
repository root — **both exit 0** (see "Baseline" below).

---

## 1. What is in the repository

A four-app npm workspace plus two shared packages, built to one static `dist/` by
`scripts/build-hub.mjs` and served by Vercel from the repository root.

| Workspace | Name | Size | Role |
|---|---|---|---|
| `apps/studio` | `assured-studio` | ~26 kLOC `src/` | **ASSURED Bench.** Design engine + QC engine + order sheets + clone decisions, in one app. Deployed at `/studio/`. |
| `apps/qc` | `assured-qc` 0.5.2 | — | Standalone Sanger-trace QC. Deployed at `/qc/`. |
| `apps/design` | `assured-crispr-designer` | — | Standalone design app with `api/` serverless lookups. Deployed at `/design/`. |
| `apps/academy-ui` | `assured-academy-ui` | 9.8 kLOC `src/` | **ASSURED Academy**, learner-facing (React 18 + TS + Tailwind). Deployed at `/academy/`. |
| `apps/academy-core` | `assured-academy-core` | headless | Missions, project envelope, seeded plate simulator, grader, data generators. No UI. |
| `packages/assured-spec` | `@assured/spec` | small | The `assured-qc-design/1` hand-off contract: schema id, edit kinds, validator. |
| `packages/assured-rules` | `@assured/rules` | small | Engine limits, donor-format tiers, `LAB_CONVENTIONS`. |

Naming note for anyone reading the specification: **"ASSURED Bench" is `apps/studio`.** There is no
`apps/bench` directory. The browser title in `apps/studio/index.html` is already
"ASSURED Bench — End-to-End CRISPR Design & Trace Analysis"; the workspace name was never renamed.

## 2. Coupling between Bench and Academy — the finding that matters most

**There is no code coupling at all. The two are joined only by plain `<a href>` links.**

- `apps/academy-ui/src/App.tsx` links to `../studio/`, `../design/`, `../qc/`.
- `vercel.json` redirects `/academy/studio/*` → `/studio/*` (and the same for `design`, `qc`).
- No Academy module imports anything from `apps/studio`. No Studio module imports anything from Academy.

Consequence: **nothing can be handed off.** A learner who designs a guide inside an Academy lesson
arrives at Bench on a blank new experiment and must retype everything.

`grep` over `apps/studio/src` for `URLSearchParams`, `location.search` and `location.hash` returns
exactly one hit, and it is unrelated (`QcView.jsx:13` resolving an asset origin). **Bench has no
URL-parameter intake of any kind**, so a deep link cannot be added purely from the Academy side.

The intake that *does* exist and is already validated is `parseProject(text)` in
`apps/studio/src/services/projectState.js`. It accepts an exported Bench experiment, rejects unrelated
JSON and malformed top-level fields, and fills defaults. A bridge should reuse that function rather
than invent a second schema. This is the single additive change Bench needs, and it is the only change
this expansion makes to Bench.

## 3. The Academy UI ships far more than it shows

`App.tsx` renders a landing page plus `CurriculumSection`. The reachable import graph is only:

```
App.tsx → CurriculumSection → LessonViewer → QuizModal → data/curriculum.ts
```

Everything else in `apps/academy-ui/src` is **built, type-checked, smoke-rendered — and unreachable by a
user**:

| Unreachable module | What it already does |
|---|---|
| `components/pipeline/UnifiedPipeline.tsx` + `Stage1Design` … `Stage5Publish` (2.3 kLOC) | The whole five-stage Design → Order → Bench → QC → Publish workbench, driven by real generated presets |
| `components/simulator/VirtualLab.tsx` + 4 stages (1.0 kLOC) | Confluency / nucleofection / plate / genotyping decision game |
| `components/missions/RareDiseaseHub.tsx` | The three GRCh38-verified missions (APOE R176C, MYD88 KO, NR2F2 2xHA) |
| `components/tools/ToolLaunchpad.tsx` | Catalogue of the 21 real sample files |
| `components/frugal/FrugalLabConfig.tsx` | Low-resource lab worksheet |
| `components/academy/AcademyHub.tsx`, `layout/Navbar.tsx`, `layout/Footer.tsx` | A tabbed shell with `TabType = 'workbench' \| 'academy' \| 'simulator' \| 'frugal' \| 'missions' \| 'suite' \| 'studio'` |
| `components/certificate/CertificateModal.tsx` | Completion record |
| `services/studioDesignService.ts`, `services/studioDeconvService.ts`, `services/pipelineStore.ts` | 1.2 kLOC of working service code |

`scripts/render-smoke.cjs` server-renders all of them ("rendered 55 components … 0 problems"), so they
are known-good; they simply have no route. **The cheapest large improvement available to this
repository is to give them one.** `types/index.ts` already declares the `TabType` union the shell
expects.

There is no router and no routing dependency. `apps/academy-ui/vercel.json` rewrites `/(.*)` →
`/index.html`, so any client-side routing works, but path-based routing would break the hub build,
which serves the same `index.html` from the `/academy/` sub-path with `base: './'`. **Hash routing is
the only option that works unchanged in both the standalone Vercel project and the bundled hub.**

## 4. Shared domain constants: real, but partial and split three ways

`@assured/rules` is a genuine single source of truth for the *design engine's* limits
(`MAX_GUIDE_CUT_DISTANCE = 15`, `MIN_PAIR_CUT_SEPARATION = 10`, `MAX_BLOCKING_CHANGES = 3`), donor
tiers and `LAB_CONVENTIONS`, and `packages/assured-rules/test/rules.test.js` fails if the lab's arm
lengths drift from the engine's defaults. That pattern is correct and should be extended, not replaced.

What is **not** in any shared package today:

| Parameter | Where it lives now | Problem |
|---|---|---|
| Neon conditions, Table 7 RNP volumes | `apps/academy-ui/src/data/benchDefaults.ts` (TypeScript) | Academy-only. Bench cannot read it; it is TS, so a plain-JS package could not import it either. |
| Cut probability, HDR rate, survival, polyclonality | `apps/academy-core/src/simulator/params.js` | Explicitly labelled **illustrative teaching defaults, not measured**. Correctly labelled, but only the headless core reads it — the UI's Virtual Lab has its own hard-coded logic. |
| Geltrex dilutions, hypoxia, CloneR2, IsoCell yields | nowhere | Stated in the protocol and in the specification, present in lesson prose only, not machine-readable. |
| CRISPR-MiX stoichiometry, refractory loci | nowhere | The method is not represented in the repository at all. |
| Donor ICC / power | nowhere | Not represented. |
| Off-target assay matrix | nowhere | Not represented. |

**A conflict the specification would silently have overwritten.** `benchDefaults.ts` records the Neon
pulse as `1200 V, 30 ms, 1 pulse`, cited to the ASSURED STAR Protocols paper. The master specification
asks for `1,200 V, 20 ms, 1 pulse`. Both are right: 30 ms is the ASSURED hiPSC protocol, 20 ms is the
CRISPR-MiX protocol. They are two protocols, not one value with a typo, and
`scripts/render-smoke.cjs` would not have caught the substitution. They must be modelled as two named
protocol variants.

## 5. Scientific-provenance culture, and what it implies for this expansion

`docs/FINDINGS.md` is unusually strict and the codebase follows it:

- the previous Academy import was audited and every invented number removed (viability percentages,
  off-target scores, prices, "87% saved", a fake chromatogram, invented R²);
- `render-smoke.cjs` enforces that removal with a `BAD` regex list (`/Lonza/`, `/Y-27632/`, `/PTO/`,
  `/Telugu et al/`, `/guarantee/i`, `/NaN/`, …) that **fails the test suite if the strings come back**;
- `params.js` carries a `provenance` field announcing it is not measured;
- mission designs are regenerated from the real Design engine and checked against GRCh38
  (`tools/verify_designs_grch38.py`, 47 checks).

**This constrains the expansion more than the specification does, and the constraint wins.** Any
number added for a simulator must carry its source, and any number that is a teaching default must say
so where a learner can see it. Of the headline figures in the specification:

| Figure | Status after checking |
|---|---|
| ASSURED pipeline, Neon 1200 V / 30 ms / 1 pulse, Table 7 | **Published.** Ludwik, Telugu, Schommer, Stachelscheid, Diecke, *STAR Protocols* 2023;4(3):102406, [doi:10.1016/j.xpro.2023.102406](https://doi.org/10.1016/j.xpro.2023.102406) (PMID 37481731). Already cited in `benchDefaults.ts`. |
| CRISPR-MiX pooled ssODN strategy, cardiomyopathy loci | **Published.** Baum, Telugu, … Diecke, Karakikes, *Mol Ther Nucleic Acids* 2026;37(1):102820, [doi:10.1016/j.omtn.2025.102820](https://doi.org/10.1016/j.omtn.2025.102820) (PMID 41674724). The abstract confirms the pooled-ssODN method, the GFP-to-BFP reporter, arm symmetry / blocking mutations / strand complementarity as the design parameters, five cardiomyopathy genes, RNP delivery and no selection. |
| KO score 79.5 ± 23, KI 57.5 ± 27, 32 loci, 22 lines | Owner-stated. Not confirmed from the abstract here. |
| IsoCell 256 chambers → ~70 single cells → ~46 clones (~65%) | Owner-stated. |
| 60 : 20 : 120 pmol sgRNA : Cas9 : ssODN, 1200 V / 20 ms / 1 pulse, 0.25 × 10⁶ cells | Owner-stated, attributed to CRISPR-MiX. Not confirmed from the abstract here. |
| Median donor ICC 43.2 %, 9,013 genes, 51 donors | **Not located.** A literature search did not find this dataset. Related published work gives 5–46 % for iPSC phenotypes across 301 donors, which brackets it, but that is not the same statistic. |

So the domain layer needs a three-valued provenance tag — `published`, `owner-stated`,
`illustrative` — and the UI must render it. The ICC explorer must take median ICC as a **user-moved
input**, not a hidden constant, so the teaching point survives whatever the true value is.

## 6. Code quality, accessibility, responsiveness

Good:

- TypeScript `strict: true`, 0 errors; `tsc` runs before every `vite build`.
- The landing/curriculum path is written with care: `aria-labelledby`, `aria-pressed`, `aria-current`,
  `role="status"`, visible `focus-visible:outline` on every interactive element, focus moved to the
  lesson panel on selection, and a `localStorage` failure path that tells the user progress is
  session-only instead of throwing.
- `render-smoke.cjs` is a real test, not a snapshot: it renders every stage × every preset, asserts the
  harness can fail, and asserts on content (96 wells, 20 guide bases, 3 PAM bases).

Gaps:

- **Accessibility is not uniform.** The unreachable components are markedly weaker than the reachable
  ones — `ToolLaunchpad.tsx` and `Navbar.tsx` use `div`-based controls and decorative icons without
  `aria-hidden`, and `Navbar`'s dropdown closes on outside mousedown but has no `Escape` handler and no
  `aria-expanded`. Routing them in without a pass over them would lower the app's accessibility floor.
- **Responsiveness is untested.** Tailwind breakpoints are used, but nothing checks them; the hub
  landing page ships a separate `assured-overview-mobile.svg`, so mobile is clearly a concern.
- **No lint.** There is no ESLint config and no `lint` script anywhere in the workspace. "Run lint" is
  not currently a thing this repository can do; `tsc --strict` plus the smoke test is the de-facto
  gate.
- **Bundle size.** `assured-studio` emits a single 731 kB JS chunk (179 kB gzip) and warns on every
  build. Pre-existing; out of scope here, but Academy must not import Bench's engines directly or it
  inherits the problem.
- **Dead `TabType` members.** `types/index.ts` declares tabs no component routes to. Harmless today,
  misleading later.

   `offsetFromEdit = -2` where cut − edit = −3. Calls and numbers are unaffected; the "(intended edit

## 9. Proposed structure for the Academy

> **Superseded on the tier count.** This section proposed six tiers. The platform owner narrowed it to
> three: school and college students, research labs (PhD students, postdocs and PIs), and core
> facilities. The material from the two retired tiers was folded in rather than deleted. The three
> rules below, the package layout and the hand-off design were all kept as written.
> `docs/ACADEMY_TIERS.md` is the current description.

Three rules, derived from sections 2–5 above:

1. **Bench is read-only to Academy.** Academy never imports `apps/studio/src`. The one change to Bench
   is an additive URL-hash intake that hands its payload straight to the existing `parseProject`.
2. **Numbers live in one plain-JS package, with provenance, and nothing else holds them.**
3. **New routes are hash routes, and the existing unreachable components get routed in rather than
   rewritten.**

```
packages/assured-protocol/           NEW. @assured/protocol — plain ESM, no deps, no framework.
  src/sources.js                     citation registry; every entry has a provenance level
  src/protocols.js                   ASSURED (STAR Protoc 2023) and CRISPR-MiX as two named variants
  src/culture.js                     hypoxia, Geltrex/Matrigel cold chain, E8 → StemFlex, CloneR2
  src/isocell.js                     256-chamber yield and seedbank model
  src/wetlabModel.js                 deviation → penalty → mechanism, for the Tier 3 simulator
  src/icc.js                         donor-ICC power model (median ICC is an argument, not a constant)
  src/offTarget.js                   off-target assay matrix for Tier 6
  src/personas.js                    the six tiers, as data
  test/*.test.js                     node --test

apps/academy-ui/src/
  router.ts                          hash router (no dependency)
  data/personas.ts                   tier → route → module map, UI metadata
  components/academy/PersonaSwitcher.tsx
  components/tiers/Tier1PatientJourney.tsx
  components/tiers/Tier2ExonSandbox.tsx
  components/tiers/Tier3WetLabSimulator.tsx
  components/tiers/Tier4PowerExplorer.tsx
  components/tiers/Tier4CrisprMixGuide.tsx
  components/tiers/Tier5CoreFacility.tsx
  components/tiers/Tier6OffTargetMatrix.tsx
  components/common/ProvenanceBadge.tsx    renders the provenance level of every number shown
  services/benchBridge.ts                  builds the Bench hand-off URL

apps/studio/src/
  services/academyHandoff.js         NEW, ~30 lines + test. Reads one hash parameter, delegates to
                                     the existing parseProject. App.jsx gains one useEffect.
```

Sequence-level content note: the specification asks for a SorCS1 exon-4 KO versus exon-25
`c.3292_3294delinsTAG` KI sandbox. `NG_029120` is **not** in `apps/academy-core/references/`, and this
repository's rule is that sequences are shipped from a reference record or not shown at all. The Tier 2
sandbox is therefore built as an explicitly-labelled **schematic** exon/isoform map that teaches the
selection rule (early constitutive exon for KO; cut as close to the edit as possible for KI, against
the engine's own `MAX_GUIDE_CUT_DISTANCE = 15`), and hands off to Bench — which loads real reference
records — for anything sequence-level. Shipping `NG_029120` and generating the designs with
`tools/design-from-refseq.mjs` would upgrade it later; that is a separate change with its own
verification.
